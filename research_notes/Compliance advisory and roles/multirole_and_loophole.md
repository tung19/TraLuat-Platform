# Multi-Role Legal AI (Investigator / Procuracy / Audit) and Legal Loophole / Gap / Ambiguity Analysis

Scope: Open-source repos and papers (GitHub, arXiv, ICAIL/JURIX/NLLP, Papers With Code) as of late 2026, for the TraLuat Vietnam legal-AI engine. Focus is on roles **beyond** the common lawyer/judge debate (we already know AgentCourt / AgentsCourt / LegalGraphRAG), plus loophole/gap/ambiguity/conflict detection. License + commercial usability captured where found.

---

## PART A — Key Question 1: Is there any open system modeling an INVESTIGATOR role (evidence↔statute mapping, case-building) or a PROCURACY/prosecution reasoning role distinctly?

### Takeaway
Multi-agent "courtroom" simulators now routinely include a **prosecutor** role (SimCourt, SAMVAD, LegalSim/L4M), but they model the prosecutor as a trial debater, not as a pre-trial **investigator building a case from evidence**. The closest work to a distinct prosecutorial/charging reasoning task is China's **Prosecution Decision Prediction (PDP)** benchmark (open data + code) and the 2021 Shanghai "AI prosecutor" prototype (not open). A true open-source **police investigator / evidence→provision mapping** agent appears to be largely **unbuilt** in open source.

### Cited Findings
- **SimCourt** (Tsinghua, arXiv:2508.17322, Aug 2025; ACL Anthology 2026) simulates Chinese criminal trials across 5 stages and 5 roles — **Judge, Prosecutor, Attorney, Defendant, Stenographer** — each agent with Profile/Memory/Strategy modules plus an external legal-article retriever over a base of 55,347 Chinese laws. Code + datasets on GitHub `Miracle-2001/SimCourt`. — [arXiv HTML](https://arxiv.org/html/2508.17322v1); [repo ref via search]; license not verified. The prosecutor here is a trial participant, not a pre-trial investigator.
- **SAMVAD** (India, arXiv:2509.03793, Sep 2025) models Judge, Prosecution Counsel, Defense Counsel and multiple Adjudicators (LLM agents) deliberating over rounds toward a consensus verdict, grounded by retrieval over the Indian Penal Code and Constitution. — [arXiv PDF](https://arxiv.org/pdf/2509.03793). Research prototype; prosecution = courtroom counsel.
- **LegalSim** (Sanket Badhe, arXiv:2510.03405v1, NLLP@EMNLP 2025, pp.370–381) is a civil-style plaintiff/defendant + stochastic judge simulator; regimes (bankruptcy default, plus **patent, tax, immigration, corporate**) are swappable JSON rule files. No criminal investigator role. — [arXiv HTML](https://arxiv.org/html/2510.03405v1). Paper is CC BY 4.0; **no code repo or software license stated**.
- **L4M** (Chen et al., 26 Nov 2025) is described as aligned with a LegalSim environment via **prosecutor, defense, and judge agents + solver-backed adjudication**, formalizing legal provisions into typed **Z3 constraints**, with prosecutor/defense-aligned agents extracting facts and statutes. — described secondhand via [EmergentMind: LegalSim](https://www.emergentmind.com/topics/legalsim); primary paper not located, treat as unverified.
- **Prosecution Decision Prediction (PDP)** (Lu et al., arXiv:2605.28464, 2026) explicitly models the **prosecutorial-review stage** (the procuratorate deciding whether to prosecute) that Legal Judgment Prediction skips. Four-way classification: Insufficient-Evidence Non-Prosecution, Statutory Non-Prosecution, Discretionary Non-Prosecution, Prosecution. It frames the task as requiring **evidence evaluation, legal subsumption, and value-based discretion**. — [arXiv HTML](https://arxiv.org/html/2605.28464).
  - **PDP-Bench:** 4,630 real Chinese prosecutorial decisions, 190 charges, Jan 2014–Mar 2026, all 31 provincial regions. Dataset on Hugging Face `Julian2002/PDP-Bench`, code on GitHub `lu-jun-yu/PDP`. **License not confirmed** (Appendix L not read).
  - Results: closed LLMs lost 0.12–0.18 Macro-F1 vs CAIL2018 charge prediction; hardest classes Statutory NP (~0.61 F1, = legal subsumption) and Discretionary NP (~0.58 F1, = value discretion). Outcome-only RL rewards (DAPO/Qwen3-8B) caused recall inflation / precision collapse; authors recommend process/rationale-level rewards.
- **Shanghai "AI prosecutor" (System 206-linked)**: 2021 prototype at Shanghai Pudong People's Procuratorate, claimed >97% accuracy producing charges from verbal case descriptions. System 206 separately assesses significance of individual evidence, arrest prerequisites, and suspect dangerousness — i.e., evidence evaluation / case-building. Still described as test-phase; **not open source**, no later rollout verified. — [Mixed News](https://mixed-news.com/en/robo-prosecutor-ai-automates-prosecutions-in-china/); [Yahoo/SCMP](https://news.yahoo.com/china-develops-ai-prosecutor-charge-220356905.html).
- **AgentsCourt** (known): judge agent refining verdicts via retrieved precedents/laws, evaluated on SimuCourt — confirms the judge+debate framing we already have. — [Moonlight review](https://www.themoonlight.io/es/review/agentscourt-building-judicial-decision-making-agents-with-court-debate-simulation-and-legal-knowledge-augmentation).

### Inferences
- The procuracy/prosecution role is well represented as a **trial-debate agent**, but the pre-trial **investigator** function TraLuat wants (điều tra viên: mapping raw evidence to specific legal provisions and constructing charges) is only partially covered — and only by PDP (classification of a decision outcome) and the closed Chinese government prototypes, not by an open reasoning/case-building agent.
- PDP's open data + code (`lu-jun-yu/PDP`, `Julian2002/PDP-Bench`) is the single most directly reusable asset for a procuracy-reasoning module, but it is Chinese-law, Chinese-language, and outputs a decision class rather than an evidence→provision mapping or a drafted charge.

### Gaps
- No open-source **police-investigator** agent that maps a fact/evidence set to candidate statutory provisions and builds a chargeable theory was found. This capability appears largely unbuilt in open source.
- Licenses for SimCourt, PDP-Bench, and PDP code were not confirmed — must be checked before any commercial reuse.
- L4M primary paper/code not located; its "solver-backed adjudication with formal guarantees" claim is unverified.

## PART A — Key Question 2: Any open system covering a COMPLIANCE / AUDIT role grounded in statutes?

### Takeaway
Statute-grounded compliance/audit is the most commercially active of the role areas, but the mature offerings are **proprietary RegTech** (CUBE, Leo, REGOLOGY, V7). Open research prototypes exist (RAGulating Compliance; a SINTEF EU-AI-Act assessment agent) but are early-stage with **no published audit-accuracy benchmarks** and licenses mostly unstated.

### Cited Findings
- **RAGulating Compliance** (arXiv:2508.09893, Aug 2025) combines a multi-agent **knowledge graph built from regulatory text** with RAG for regulatory QA, grounding answers via triplet-level retrieval. — [arXiv abs](https://arxiv.org/abs/2508.09893v1). Most substantive open academic source; license/benchmark not verified.
- **SINTEF compliance-assessment agent**: LLM agents that extract, label, and assess data-pipeline artifacts against legal requirements (e.g., EU AI Act), decomposing the task into modular agent sub-tasks guided by actor role and system risk level to mitigate token limits; prototype shows feasibility but flags trust, context interpretation, and output validity as open challenges. — [SINTEF](https://www.sintef.no/en/publications/publication/10325015).
- **"LLM Agents in Law: Taxonomy, Applications, and Challenges"** (arXiv:2601.06216, 2026) notes multi-agent compliance systems that decompose obligations into **planning, execution, and verification** roles, and names commercial tools REGOLOGY and V7 Labs for data-protection/privacy compliance. — [arXiv PDF](https://arxiv.org/pdf/2601.06216).
- **Commercial RegTech** (vendor roundup, not peer-reviewed): "Leo" decomposes hundreds-of-pages statutes into structured knowledge graphs for a network of LLM agents; CUBE combines OCR + a legal LLM + a regulatory knowledge graph for cross-regime change management. — [A-Team Insight](https://a-teaminsight.com/blog/ai-in-action-11-firms-rewiring-compliance-for-speed-clarity-and-control/).

### Inferences
- The dominant architecture for statute-grounded compliance is **regulatory knowledge graph + RAG + role-decomposed agents (plan/execute/verify)** — a reusable pattern for a TraLuat "auditor" role, though all mature implementations are closed.
- Compliance/audit is better served by existing tooling than investigator/procuracy, so TraLuat's differentiation there is lower; the opportunity is a **Vietnam-statute-grounded** version.

### Gaps
- No open benchmark for statute-grounded compliance audit accuracy was found.
- No open-source compliance auditor specifically grounded in Vietnamese statutes found.

## PART B — Key Question: Any tool/paper detecting LEGAL LOOPHOLES, gaps, ambiguities, conflicts, or under-specification in statutes/regulations? How is the ethical dual-use handled?

### Takeaway
This is an active but **early** research area with several concrete 2025–2026 artifacts. The strongest are: **neuro-symbolic formalization** for ambiguity/inconsistency detection (IRC §121 Prolog paper; the tax-loophole DSL paper), a **manually-built statutory-conflict dataset** (Clash-of-Leges, Italian Constitutional Court), **multi-agent contradiction detection** (LegalWiz), and **procedural-exploit discovery** (LegalSim). Pure-LLM approaches are unreliable (hallucination 69–88% without grounding); the reliable methods all add a **symbolic/solver layer**. Dual-use is acknowledged unevenly: LegalSim addresses it head-on; the tax-loophole paper leaves it largely implicit.

### Cited Findings — Tools / methods
- **Tax-loophole DSL** — "Can AI expose tax loopholes? Towards a new generation of legal policy assistants" (Fratrič, Holzenberger, Restrepo Amariles, arXiv:2503.17339, Mar 2025). Models corporate incorporation as a transition system; encodes legal rules as **Prolog rules tagged with provision reference codes** (traceability); NL interface constrained to produce DSL expressions; randomized best-first search samples tax plans; utility-profile analysis flags loopholes (economically-equivalent plans should give ~constant utility, so variance = loophole). Case study: **"Double Irish with Dutch Sandwich"** reconstructed; PyGol rule learner acc 0.981 / F1 0.743; Theorem 2 gives a welfare guarantee for a rule set that removes underpaying strategies. GitHub `fratric/Rules2Lab` linked; **no software license stated**; open-source adaptation is future work. — [arXiv HTML](https://arxiv.org/html/2503.17339v1).
- **IRC statutory-inconsistency formalization** — "LLM-Assisted Formalization Enables Deterministic Detection of Statutory Inconsistency in the Internal Revenue Code" (arXiv:2511.11954v1, 15 Nov 2025). GPT-4o drafts Prolog rules for IRC §121, refined in SWISH with GPT-5; the Prolog model varies inputs to find where two readings of an ambiguous phrase ("whichever is applicable") diverge (an "inconsistency zone" ≈ 1–23 months). **Hybrid Prolog: 100% detection of the known inconsistency vs 33% for GPT-4o alone** (1 of 3 prompting strategies). GitHub `martians-sheep/miniature-parakeet`; **no license stated**. This is **ambiguity/inconsistency** detection, not exploitable-gap detection. Caveats: single case study, one known inconsistency as ground truth, "deterministic" = execution not formalization correctness, no detection of *unknown* inconsistencies yet. — [alphaXiv](https://alphaxiv.org/overview/2511.11954v1).
- **Clash-of-Leges** (Italiani, Moro, Ragazzi; Expert Systems with Applications, 2026) — bilingual (IT/EN) **manually-built** dataset derived from Italian Constitutional Court rulings that explicitly identify conflicts between provisions. Three tasks: **conflict detection** (do two provisions conflict?), **conflict explanation generation**, **article retrieval**. Positioned as more realistic than prior synthetic/semi-synthetic (EN/ZH) benchmarks. — [UniBO CRIS record](https://cris.unibo.it/handle/11585/1027358); [full-text PDF](https://cris.unibo.it/retrieve/handle/11585/1027358/accc342e-63d5-4110-a167-c66f47110271/1-s2.0-S0957417425037972-main%20%281%29.pdf). Dataset release location/license not verified.
- **LegalWiz** (Mantravadi et al., arXiv:2510.03418v2, cs.AI/cs.MA) — "A Multi-Agent Generation Framework for **Contradiction Detection in Legal Documents**." Includes LLM contradiction *injection* for data generation and a contract-benchmarking focus. Paper CC BY 4.0; **no code repo found in the PDF** (body text was unreadable, so agents/results not fully confirmed). — [arXiv abs](https://arxiv.org/abs/2510.03418v2).
- **CLAUSE** — generates contradictions in contracts, covering both modifications that conflict with statutory requirements and intra-document logical inconsistencies (benchmark cited alongside the above). — surfaced via conflict-detection search; primary source not fetched.
- **LegalSim** (arXiv:2510.03405v1) — discovers emergent **"procedural exploit chains"** (cost-inflating discovery sequences, calendar-pressure via automatic-stay gates, settlement pressure backed by sanction risk) that are each procedurally valid but collectively harmful. Methods: heuristic / direct-LLM (GPT-4o) / contextual bandit / PPO self-play (PPO win rate 0.742; bandit most consistent; no MCTS). Rule engine is swappable JSON incl. a **tax** regime. — [arXiv HTML](https://arxiv.org/html/2510.03405v1).
- **Greek legislative semantic-audit pipeline** — "From Parliamentary Rhetoric to Enacted Law" (arXiv:2606.00030) — NLP pipeline auditing enacted law for legal vulnerabilities, with a **typology of loopholes** (its Section 4.3). — [arXiv PDF](https://arxiv.org/pdf/2606.00030). Not fetched in full; typology could be a useful taxonomy for TraLuat.
- **LegalLens Shared Task 2024** (arXiv:2410.12064) — detecting legal violations in unstructured text and linking them to statutes; NER reasonably advanced but legal NLI still has "significant room." — adjacent (violation→statute linking), not gap detection. — [arXiv PDF](https://arxiv.org/pdf/2410.12064).

### Cited Findings — Reliability & dual-use framing
- **Pure-LLM unreliability**: LLMs answering legal queries without retrieval grounding hallucinated **69–88%** of the time (Dahl et al. 2024, cited in conflict-detection literature); LLMs "still struggle to reason over these conflicts or reliably identify them." — via conflict-detection search results. This is the core argument for a symbolic/solver layer.
- **LegalSim dual-use (strongest explicit treatment)**: defensive framing = identifying failure modes before deployment supports due process and "red-teaming legal rule systems, not just models." Directly states the same insights "could enable misuse," with mitigations: confine analysis to simulation, avoid jurisdiction-specific guidance, emphasize safeguards; findings "not grounded in real judicial data," should inform not replace human governance. — [arXiv HTML](https://arxiv.org/html/2510.03405v1).
- **Tax-loophole paper dual-use (weak/implicit)**: emphasizes public benefit (public evaluation of new laws, widening access to legal analysis) and frames loophole-finding as helping **policymakers close gaps and improve social welfare**; it does **not** directly address the risk that the tool helps taxpayers avoid tax — the tension is implicit in its RQ1 goal of making tax planning "broadly available." — [arXiv HTML](https://arxiv.org/html/2503.17339v1).

### Inferences
- A defensible TraLuat loophole/gap feature should (a) use a **symbolic/solver layer** (Prolog/Z3) over LLM extraction, given pure-LLM unreliability; (b) keep **provision-level traceability** (as the tax-loophole paper's reference-tagged Prolog does); and (c) adopt an explicit **defensive dual-use posture** modeled on LegalSim (frame output as "where the law is unclear/silent/contradictory for the drafter/auditor to fix," not "how to exploit it").
- The field has **no mature, general-purpose statutory loophole detector** — all artifacts are narrow (single statute section, single scheme, or single jurisdiction's conflict corpus). This is a genuine open opportunity for a Vietnam-focused engine, but also a warning that the problem is hard and largely unsolved.

### Gaps
- No open-source tool detects loopholes/gaps across a **whole code/corpus** (all are single-section or single-case studies).
- Licenses for the loophole/conflict artifacts (IRC Prolog repo, Rules2Lab, Clash-of-Leges, LegalWiz) are **unstated or unverified** — commercial reuse status unknown; assume restricted until checked.
- No Vietnamese-language or Vietnam-law loophole/conflict/ambiguity dataset or tool was found.
- Greek-pipeline loophole typology (Sec 4.3) and LegalWiz's agent roster/results were not read in full (PDF bodies unreadable / not fetched).
